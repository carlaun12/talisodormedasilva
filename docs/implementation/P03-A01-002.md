## Implemented slice and boundaries

One physical module, `:app`, with packages under `com.talisodormedasilva`:

| Package | Responsibility |
|---|---|
| `domain` | Dated item, inflow/outflow direction, month grouping, read-only repository contract |
| `presentation` | Monthly calendar, immutable screen state, ViewModel, selection/navigation events |
| `data.local` | Room database, entity, DAO, date/direction mapping, repository implementation |
| `platform` | Android application/activity and manual dependency construction |

Presentation reads the application-owned contract, never a DAO. Domain imports neither Android UI, Compose, nor Room.
The ViewModel owns state, preserves selected dates through SavedStateHandle, cancels obsolete month observations, and retains read failures while showing a generic error message.

The screen has a Monday-first monthly grid, previous/next month navigation, date selection, per-day inflow/outflow item counts, and selected-date item labels with explicit direction text.
Counts are item indicators, not monetary totals. Shorter months clamp the selected day. Loading, empty, and read-error states are distinct.
The production database starts empty. Deterministic financial records exist only in tests; no fixture insertion occurs in production startup.

No CRUD screens, amounts/currencies/calculations, specialized card semantics, installments, balances, categories, recurrence, notifications, imports, reports, accounts, network/backend, synchronization, KMP, Desktop, extra modules, or DI framework were introduced.
A card obligation is represented using the same outflow direction as any other obligation.
No Etar source or feature set was copied.

## Room schema and lifecycle

Database: `financial-calendar.db`, version **1**. One table: `financial_items`.

| Column | SQLite type | Purpose |
|---|---|---|
| `id` | INTEGER, generated primary key, NOT NULL | Stable item identity |
| `epochDay` | INTEGER, NOT NULL, indexed | Date without timezone conversion |
| `label` | TEXT, NOT NULL | Minimal meaningful item description |
| `direction` | TEXT, NOT NULL | `INFLOW` or `OUTFLOW`, mapped to an application enum |

Month queries use a half-open date range and order by date, then identity.
The DAO exposes observation and an insert operation for persistence validation; there is no product mutation workflow.
Invalid stored directions fail mapping rather than silently becoming outflows.
Room-generated schema: `app/schemas/com.talisodormedasilva.data.local.FinancialDatabase/1.json`.
There is no predecessor schema and therefore no migration edge yet. Future changes must increment the version, supply a non-destructive migration, and test it.
No destructive migration fallback or main-thread query allowance is configured. Tests verify reopening and rejection of a missing migration.
Cloud backup and device transfer are explicitly excluded through Android backup resources, preserving the initial local-data boundary.
